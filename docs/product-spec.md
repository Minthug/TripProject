# NextMate 기본 제품 스펙

## 제품 정의

NextMate는 여행자의 일정, 숙소, 현재 위치를 기준으로 다음 목적지와 이동
방법을 안내하는 Flutter 기반 iOS·Android 여행 도우미다.

일정 설계의 기본 기준점은 숙소다. 여행 중에는 현재 위치를 우선하고, 하루의
첫 출발지와 마지막 귀가 지점에는 해당 날짜의 숙소를 사용한다.

## 지도 플랫폼 결정

지도와 장소 데이터의 기본 플랫폼은 **Google Maps Platform**으로 고정한다.

| 기능 | 기본 기술 |
|---|---|
| iOS·Android 지도 표시 | Google Maps SDK (`google_maps_flutter`) |
| 호텔·관광지 이름 검색 및 자동완성 | Google Places API |
| 장소 상세 정보와 공식 주소 확인 | Google Places API Place Details |
| 좌표와 현지 주소 변환 | Google Geocoding API |
| 자동차·도보·대중교통 경로와 예상 시간 | Google Maps 경로 API 계열 |
| 택시 호출 연결 | Uber 딥링크 |

현재 프로토타입의 지도와 검색 결과는 UI 검증용 샘플이다. 실제 지도 구현 시
직접 그린 지도 배경을 Google Maps 위젯으로 교체한다.

## 숙소 추가 흐름

1. Stay Planner에서 `+ Stay`를 누른다.
2. Google Places 자동완성으로 호텔명 또는 주소를 검색한다.
3. 선택한 장소를 Google Maps에 표시한다.
4. 사용자가 지도를 움직여 실제 승하차 입구 핀을 확인하거나 조정한다.
5. 체크인·체크아웃 날짜와 시간을 정한다.
6. 기존 숙박 구간과 겹치거나 비는 날짜를 검사한다.
7. 숙소를 여행 일정에 저장한다.

검색에 없는 숙소, 숙박 공유 서비스, 개인 주소도 중앙 고정 핀을 이용해 직접
등록할 수 있어야 한다.

## 숙소 데이터 규격

장소 중심 좌표와 실제 승하차 입구 좌표를 분리해 저장한다.

| 필드 | 설명 |
|---|---|
| `placeId` | Google Places 장소 ID. 직접 지정한 위치는 비어 있을 수 있음 |
| `displayName` | 여행자에게 표시할 숙소명 |
| `localName` | 현지어 숙소명 |
| `formattedAddress` | 현지어 공식 주소 |
| `latitude`, `longitude` | Google 장소 중심 좌표 |
| `entranceLatitude`, `entranceLongitude` | 사용자가 확인한 승하차 입구 좌표 |
| `checkInAt`, `checkOutAt` | 현지 시간 기준 체크인·체크아웃 |
| `timeZoneId` | 숙소가 위치한 지역의 시간대 |
| `luggageStorage` | 체크인 전·체크아웃 후 짐 보관 가능 여부 |
| `locationSource` | `googlePlaces` 또는 `manualPin` |

택시 딥링크와 기사 번역 카드에는 장소 중심점이 아니라 확인된 입구 좌표와
현지어 주소를 우선 사용한다.

## 다중 숙소 규칙

- 여행의 모든 숙박일은 하나의 숙소 구간에 포함되어야 한다.
- 숙소 구간끼리 날짜가 겹치거나 비면 사용자에게 알린다.
- 체크아웃과 다음 체크인이 같은 날짜라면 숙소 이동일로 표시한다.
- 이동일에는 짐 보관, 숙소 간 이동, 관광 시작 위치를 별도로 계획한다.
- 주변 랜드마크 추천은 사용자가 선택한 숙소를 기준으로 계산한다.

## 유연한 하루 일정 규칙

- 일반 관광지는 체류 시간이나 고정 방문 시간을 요구하지 않는다.
- 하루 일정은 시간표가 아니라 사용자가 가고 싶은 장소의 순서로 관리한다.
- 예약, 공연, 지정 입장권처럼 실제 시간이 있는 장소만 시간을 고정한다.
- 장소 카드에는 해당 날짜의 영업 여부, 개장·폐장, 입장 마감 정보를 표시한다.
- 현재 위치에서 예상 도착 시각과 폐장 시각이 가까우면 경고하되 방문을 막지 않는다.
- 휴관 장소는 방문 가능한 다른 날짜로 옮길 수 있게 제안한다.
- 순서 추천은 운영시간과 이동 거리를 함께 사용하며 사용자가 다시 정렬할 수 있다.
- 숙소는 일정 항목으로 강제하지 않고 `숙소로 돌아가기` 행동으로 제공한다.

## 전체 일정 보기 규칙

- 여행 시작일부터 종료일까지 모든 날짜를 빠짐없이 한 화면에 표시한다.
- 각 날짜에는 그날 밤의 숙소를 표시하고, 체크아웃과 다음 체크인이 같은 날이면 `숙소 이동일`로 강조한다.
- 숙소 이동일에는 체크아웃·체크인 시각과 두 숙소 사이의 공백, 짐 보관 필요 여부를 함께 보여준다.
- 예약이 없는 관광 일정은 분 단위 시간표로 만들지 않고 `오전이 비어 있음`, `저녁이 비어 있음`처럼 열린 구간으로 표현한다.
- 휴관일에 등록된 장소와 시간이 겹치는 예약은 충돌로 표시하고 해결이 필요한 날짜 수를 요약한다.
- `문제만 보기` 필터로 휴관·예약 충돌이 있는 날짜만 모아볼 수 있게 한다.
- 날짜 카드를 누르면 해당 날짜의 유연한 하루 일정 화면으로 이동한다.

## 관광지 검색·추가 규칙

- 선택한 날짜와 그 날짜의 숙소를 화면 상단에 유지한다.
- Google Maps와 추천 목록을 동시에 제공하고 숙소에서의 이동 시간을 표시한다.
- 검색 결과와 장소 상세에는 영어명, 현지어명, 현지 주소를 함께 표시한다.
- 선택한 날짜의 영업 여부, 폐장 시각, 입장 마감과 특별 휴관을 먼저 확인한다.
- 휴관 장소는 막아버리지 않고 방문 가능한 가장 가까운 날짜를 제안한다.
- 체류 시간은 요구하지 않고 날짜와 장소 순서만 일정에 추가한다.
- 장소를 추가한 뒤에도 사용자가 자유롭게 순서를 바꾸거나 다른 날짜로 옮길 수 있다.

## 관광지 상세 및 일정 편집 규칙

- 검색 결과의 장소 카드나 지도 핀을 누르면 같은 관광지 상세 화면을 연다.
- 상세 화면에는 선택 날짜의 운영시간과 마지막 입장 시각을 우선 표시한다.
- 장소 중심점과 별도로 실제 방문객 입구 이름·좌표를 저장하고 지도에서 확인할 수 있게 한다.
- 예약 상태는 `예약 필수`, `예약 권장`, `현장 구매 가능`, `예약 불필요`로 구분한다.
- 장소명, 방문객 입구명, 공식 주소는 여행자 언어와 현지어를 함께 제공한다.
- 일정 추가 전에는 방문 날짜를 선택하고 `일정에 추가`를 실행한다.
- 이미 추가된 장소는 동일 화면을 편집 모드로 열어 날짜 변경, 저장, 일정 삭제를 제공한다.
- 선택 날짜가 휴관일이면 추가를 막고 여행 기간 안에서 가장 가까운 운영일을 추천한다.
- 관광지 상세의 입구 좌표와 현지어 주소는 이후 길안내와 택시 기사 카드에서도 재사용한다.

## 위치 및 API 보안

- Google Maps API 키는 iOS 번들 ID와 Android 패키지·서명으로 각각 제한한다.
- API 키와 비밀 값은 Git 저장소에 직접 커밋하지 않는다.
- 현재 위치는 사용자의 명시적인 권한을 받은 뒤 사용한다.
- 백그라운드 위치는 여행 중 실시간 안내에 꼭 필요한 범위에서만 요청한다.

## 가독성 및 글자 크기

- 본문과 보조 정보의 기본 크기는 기존 시안보다 15% 크게 제공한다.
- 사용자는 `A−`, `A+` 버튼으로 글자 크기를 100%, 115%, 130% 중 선택할 수 있다.
- 선택한 글자 크기는 앱 전체 화면에 즉시 반영하고 기기에 저장한다.
- 색상만으로 영업·휴관·경고 상태를 구분하지 않고 아이콘과 문구를 함께 사용한다.
- 큰 글자에서도 핵심 행동 버튼과 운영시간이 잘리거나 겹치지 않아야 한다.

## 관광객용 대중교통 안내 규칙

- 역 이름은 영어와 현지어를 함께 표시한다.
- 노선 번호, 노선 색상, 승차 방향과 반대 방향을 명확히 구분한다.
- 역 출입구 번호, 환승 표지판, 하차 후 출구를 단계별로 안내한다.
- 몇 정거장 이동하는지 보여주고 하차 한 정거장 전에 알린다.
- 교통카드 사용법, 승하차 태그, 예상 요금과 막차 정보를 제공한다.
- 엘리베이터와 접근 가능한 대체 출구 정보를 표시한다.
- 지하 GPS 오차를 고려해 `탑승했어요`, `내렸어요` 같은 수동 진행을 지원한다.
- 초기 버전은 정밀 지하 위치 추적 대신 경로·시간표를 기준으로 남은 정거장을 추정한다.
- 사용자 확인은 `탑승했어요`, `환승했어요`, `내렸어요` 세 시점으로 최소화한다.
- 자동 확인이 어려운 구간은 현재 위치를 단정하지 않고 `예상`, `약`으로 표시한다.
- 역무원에게 보여줄 현지어 문장과 음성 재생 기능을 제공한다.
- 선택한 경로는 네트워크가 불안정해도 볼 수 있도록 오프라인 저장을 지원한다.

## 이동수단 비교 규칙

- 현재 위치에서 다음 목적지까지 Uber, 대중교통, 도보를 한 화면에서 비교한다.
- 모든 수단에 예상 소요 시간, 도착 예정 시각, 예상 비용을 같은 순서로 표시한다.
- Uber는 호출 차량의 도착 시간과 교통 상황을 반영한 시간·요금 범위를 표시한다.
- 대중교통은 환승 횟수와 정류장까지의 도보 시간을 함께 표시한다.
- 도보는 거리와 경사 등 여행자가 출발 전에 알아야 할 조건을 표시한다.
- 가장 빠른 수단, 비용 효율이 좋은 수단, 무료 수단을 문구와 아이콘으로 구분한다.
- 시간과 비용은 예상치이며 교통·운행 상황에 따라 바뀔 수 있음을 명시한다.
- Uber 선택은 호출 전 확인 화면으로, 대중교통 선택은 단계별 안내로 연결한다.
